**You need** admin access to Gemini Enterprise, an Evinced Site Scanner account, and about 15 minutes.

## What you'll enter

Every value used in steps 4, 6 and 7. Copy them exactly.

| Field | Value |
| --- | --- |
| MCP Server URL | `https://site-scanner-mcp.evinced.io/mcp` |
| Authorization URL | `https://site-scanner-mcp.evinced.io/authorize` |
| Authorization URL Parameters | _Leave empty_ |
| Token URL | `https://site-scanner-mcp.evinced.io/token` |
| Client ID | `iIHIYWjC4dNEWfjVw4g0knyUpgmNolGS` |
| Client Secret | _Leave empty_ |
| Scopes | `openid profile email offline_access` |
| Enable PKCE Support | On |
| Use HTTP Basic Authentication | Off |
| Data connector name | `Evinced Site Scanner` |
| Actions to enable | All of them |

<Aside type="tip" title="Good to know">
	- **Why fill in OAuth by hand?** Gemini Enterprise doesn't discover sign-in settings on its own, so you enter them once. The URLs point at the Site Scanner server, which hands the sign-in to Evinced.
	- **No client secret.** The Site Scanner server keeps the secret on its side, and PKCE protects the sign-in, so leave the secret empty and HTTP Basic auth off.
	- **One tool makes changes.** Every tool only reads your Evinced data except **Create Property**, which adds a property to your account. To keep Gemini read-only, leave it disabled in step 7.
	- **Everyone signs in as themselves.** The sign-ins in steps 5 and 7 are only for the admin. Each person authorises Evinced Site Scanner in the Gemini app with their own Evinced account (step 8) and sees only what that account can access.
</Aside>

## Part 1 · Before you start

_A Google Cloud admin checks this once._

### Step 1 · Check the MCP policy

Google Cloud can stop Gemini Enterprise from connecting to custom MCP servers. If the policy below reads **Enforced** for your project, turn it off for that project only; the rest of your organization keeps it. You need the **Organization Policy Administrator** role.

<Steps>

1. Open **IAM & Admin › Organization policies**, find **Disable custom MCP server connector for Gemini Enterprise**, and click **Manage policy**.
2. Under **Policy source**, choose **Override parent's policy**.
3. Under **Rules**, keep one rule set to **Not enforced** (**Add a rule** if there is none).
4. Click **Set policy**. Its status then reads **Not enforced**.

</Steps>

<Figure
	src={policyedit}
	width={540}
	alt="The Edit policy page for Disable custom MCP server connector for Gemini Enterprise, with Override parent's policy as action 2, a rule set to Not enforced as action 3 and the Set policy button as action 4."
/>

<Aside>
	Changes can take up to 15 minutes to reach Gemini Enterprise. Constraint:
	`discoveryengine.managed.disableCustomMcpServerConnector`
</Aside>

## Part 2 · Add the connector

_A Gemini Enterprise admin does this once._

### Step 2 · Start a new data store

In the Google Cloud console, open **Gemini Enterprise** in your project and select your app.

<Steps>

1. Open **Connected data stores**.
2. Click **+ New data store**.

</Steps>

<Figure
	src={stores}
	width={760}
	alt="The Gemini Enterprise console, with Connected data stores in the menu as action 1 and the New data store button as action 2."
/>

### Step 3 · Choose Custom MCP Server

On **Select a data source**, scroll down to **MCP servers**.

<Steps>

1. On the **Custom MCP Server** card, click **Add MCP server**.

</Steps>

<Figure
	src={source}
	width={760}
	alt="The Select a data source page scrolled to MCP servers, with the Custom MCP Server card highlighted as action 1."
/>

### Step 4 · Enter the server details

Keep **OAuth 2.0** selected. Leave **Authorization URL Parameters** and **Client Secret** empty.

<Steps>

1. **MCP Server URL**

   ```text
   https://site-scanner-mcp.evinced.io/mcp
   ```

2. **Authorization URL**

   ```text
   https://site-scanner-mcp.evinced.io/authorize
   ```

3. **Token URL**

   ```text
   https://site-scanner-mcp.evinced.io/token
   ```

4. **Client ID**

   ```text
   iIHIYWjC4dNEWfjVw4g0knyUpgmNolGS
   ```

5. **Scopes**

   ```text
   openid profile email offline_access
   ```

6. **Enable PKCE Support**: on
7. **Use HTTP Basic Authentication**: off
8. Click **Verify Auth**.

</Steps>

<Figure
	src={form}
	width={500}
	alt="The custom MCP server form, with actions 1 to 8 marking the server, authorization and token URLs, the client ID, the scopes, PKCE on, HTTP Basic authentication off and the Verify Auth button."
/>

### Step 5 · Sign in to verify

**Verify Auth** opens the Evinced sign-in in a pop-up.

<Steps>

1. Enter your Evinced email, click **Continue**, and finish signing in. The pop-up closes on its own.

   <Figure
   	src={login}
   	width={380}
   	alt="The Evinced log-in pop-up, with the email field and Continue button highlighted as action 1."
   />

2. Check for **Successfully logged in.**

   <Figure
   	src={success}
   	width={640}
   	alt="Back in Gemini Enterprise, a green Successfully logged in message under the PKCE and HTTP Basic authentication settings, highlighted as action 2."
   />

3. Scroll down and click **Continue**.

</Steps>

### Step 6 · Name it and create

Location stays **global (Global)**. The tag and the sensitive data protection policy are optional.

<Steps>

1. **Data connector name**: `Evinced Site Scanner`
2. Click **Create**. You land on the new connector's page, and **Evinced Site Scanner** is listed under Connected data stores.

</Steps>

<Figure
	src={name}
	width={760}
	alt="The Configure your data connector page, with the data connector name Evinced Site Scanner as action 1 and the Create button as action 2."
/>

<Aside type="tip">
	If Create reports **Operation denied by org policy**, complete [step 1](#step-1--check-the-mcp-policy). The change can take up to 15 minutes; then click **Create** again.
</Aside>

### Step 7 · Turn on the tools

A new connector starts with every tool turned off. Gemini calls them actions.

<Steps>

1. On the connector's page, click **Go to actions**.

   <Figure
   	src={created}
   	width={760}
   	alt="The new connector's page, with a banner saying its actions are disabled and the Go to actions button highlighted as action 1."
   />

2. Click **Reload custom actions** and sign in to Evinced in the pop-up. The Site Scanner tools appear, all **Disabled**.
3. Tick **Select all rows**.
4. Click **Enable actions**. It appears once rows are selected.
5. Check that every action shows **Enabled**.

   <Figure
   	src={actions}
   	width={760}
   	alt="The Actions tab, with Reload custom actions as action 2, the select-all checkbox as action 3, and every Site Scanner action's status reading Enabled."
   />

</Steps>

<Aside>Gemini asks people to confirm each tool call before it runs.</Aside>

## Part 3 · Start using it

_Everyone does this once, each with their own Evinced account._

### Step 8 · Connect your Evinced account

Gemini works only with what your Evinced account can access.

<Steps>

1. Open your Gemini Enterprise app and click **Sources**, the sliders icon under the prompt box.
2. Next to **Evinced Site Scanner**, click **Authorise** (**Authorize** in US English) and sign in with your Evinced account.
3. The pop-up closes and the **Evinced Site Scanner** toggle is on.

</Steps>

### Step 9 · Confirm the connection

The **whoami** tool only reads. It's the quickest way to check which account Gemini is using.

<Steps>

1. Start a chat and ask:

   ```text wrap
   Use the Evinced Site Scanner connector to run its whoami tool.
   ```

2. Gemini shows the tool it wants to run. Click **Send**.

   <Figure
   	src={askConfirm}
   	width={700}
   	alt="Gemini Enterprise asks before it runs the whoami tool, with the Send button highlighted as action 2."
   />

3. Gemini replies with the Evinced account and tenant it's using.

   <Figure

</Steps>

### Step 10 · Ask a real question

Ask in plain language. Gemini picks the Site Scanner tool that fits.

<Steps>

1. Ask about your sites, for example:


2. Check the details Gemini will send (here, how many properties) and click **Send**.

   <Figure

## If something goes wrong

| What you see | What to do |
| --- | --- |
| **"Operation denied by org policy"** when you click Create | Your organization still blocks custom MCP servers for Gemini Enterprise. Complete [step 1](#step-1--check-the-mcp-policy), wait a few minutes (up to 15), and click **Create** again. |
| **"Callback URL mismatch"** when you click Verify Auth | Evinced's sign-in doesn't recognise Gemini Enterprise. Email [support@evinced.com](mailto:support@evinced.com). |
| **"No actions are enabled"** after you create the connector | Gemini can't use any tool yet. Complete [step 7](#step-7--turn-on-the-tools): reload the actions, select all, and click **Enable actions**. |
| **Evinced Site Scanner shows "Authorise"** (or "Authorize") in the Gemini app | That's expected the first time. Click it and sign in with your Evinced account ([step 8](#step-8--connect-your-evinced-account)). |
